## What was before

- A successful price apply could update the visible method price immediately while the row still showed stale `Needs update` until a full page refresh.
- Live managed rows with all methods disabled could still present as row-level `Active`.
- Header and top navigation used a narrower container than the page content, so their left/right edges did not align with the content area.

## Price status flicker root cause

The status builder compared live managed WooCommerce method prices against the dataset/settings default price for each enabled method. After a legitimate Shipping Editor price change, WooCommerce contained the requested live price, but the default future-setup price could still differ. That made the row compute `Needs update` even though the editor had just successfully written and displayed the requested live value.

The post-apply verification overlay also only distinguished "verification pending" versus cleared state. It did not preserve a failed or mismatch phase for affected rows.

## Fix implemented

- Removed default-vs-live price comparison from row status derivation. Settings defaults remain future setup defaults, not the source of truth for live edited WooCommerce prices.
- Added post-apply phases: `verifying`, `verified`, `failed`, and `mismatch`.
- During verification, affected rows show `Updating...` and method cells preserve the expected applied price/status values.
- If diagnostics confirms the requested value, the row returns to its live managed status.
- If diagnostics fails, the UI keeps the expected visible value and shows: `Update sent, but verification failed. Refresh diagnostics.`
- If diagnostics returns a different live value, affected managed rows may show `Needs update` again with a mismatch warning.

## Disabled row status behavior

- Added `Methods disabled` row status when all registry-owned managed methods for a wilaya are disabled.
- Added `Partially active` row status when some registry-owned managed methods are enabled and some are disabled.
- Disabled method cells remain read-only/muted with a `Disabled` badge.
- Disabled managed methods are not treated as missing setup and do not imply a price update by themselves.
- The row-level switch continues to represent managed method enable/disable, not zone deletion.

## Header/tabs layout alignment

- Header, top navigation, main content, and footer now use the same max-width and horizontal padding.
